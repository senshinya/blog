# 三语言（中／英／日）i18n 设计

日期：2026-09-09

## 背景

站点当前是纯中文。`blog.config.ts` 的 `language: 'zh-CN'` 是「本站是什么语言」的单一常量，被四处消费：`nuxt.config.ts` 的 `site.defaultLocale`、`Date.vue` 的日期格式化、`Search.vue` 的 `Intl.Segmenter` 分词、`atom.xml.get.ts` 的 feed language。依赖树里没有 `@nuxtjs/i18n`，也没有 vue-i18n。

`app/` 下 141 个 vue/ts 文件里 97 个含中文，剔除纯注释行后约 314 行是界面文案。文章分类用中文字符串（`折腾`／`项目`／`笔记`／`日常`）同时充当数据 key 和展示名。

本次改动引入中、英、日三种语言。文章、友链、游记的译文由作者自行补写，本设计只负责让这些译文有地方放、能被正确路由和呈现。

## 目标

- 中文 URL 逐字节不变，保护历史链接、评论线程 key 与统计连续性。
- 首次进入按浏览器语言落地，跳转一次即固化；此后一律使用记住的偏好。
- 某页缺少偏好语言的译文时不产生 404，也不中断读者浏览。
- 界面文案漏翻在编译期暴露，而非上线后才发现。
- 新增语言时不需要逐处手工登记路由和 routeRules。

## 非目标

- 不做内容级回落。缺译文的页面不以其他语言的内容顶替，避免同内容双 URL 与 hreflang 失真。
- 不合并中英日的评论线程。三种语言各自成线程。
- 不翻译碎语（`/memos`，外部 API 的中文短句）与娱乐页（`/media`，Bangumi 的专有名词）的内容，只翻它们的界面壳。
- 不翻译 slug。三种语言共用同一套英文路径。
- 不翻译源码注释。那些是写给作者自己的。

## 已选方案

内容按语言分目录，每语言一个 Nuxt Content collection，三种语言路径对等；路由用 `prefix_except_default` 且 `defaultLocale: 'zh'`；语言决策由一个构建期生成的清单驱动，在客户端全局中间件里执行。

路径对等在本仓库是免费的：44 篇文章的 slug 已经全是 ASCII 英文（`anti-chronic-gastritis`、`tech-about-gfw`），且 0 篇使用 `permalink`。因此文件路径本身就是语言无关的身份标识，Hugo 那套 `translationKey` 元数据层完全不需要。

### 未采用方案

**文件名后缀（`foo.en.md`）**：Nuxt Content v3 不支持，语言码会漏进 `stem`；社区的 `localeStrategy: 'filename_suffix'` 请求（nuxt/content#2835）至今未实现。

**单 collection + locale 字段**：`source: { include: 'zh/**', prefix: '' }` 会剥掉语言段，使现有的 `content:file:afterParse` hook 无需改动；单 collection 方案下路径会带上 `/zh/`，该 hook 与所有 `.path()` 查询都要重新认识语言。此外全站 8 处 `queryCollection` 调用点里绝大多数是聚合查询（列表、统计、订阅源、搜索、上下篇），它们本就应当按语言隔离，per-locale collection 免费提供这层隔离，而 locale 字段方案要求每处都记得加过滤，漏一处即静默混语言。

**`no_prefix` 策略**：与 SSG 直接冲突，一个 URL 不可能有三份静态产物。

**分域名**：个人博客的过度设计，且评论服务的 `SITE_ORIGIN` 需同时收三个域。

**清单内联进每页 payload**：只能知道当前页有哪些语言，而中间件需要在导航前判断目标页，能力不足。

**中间件运行时查 Content 客户端 DB**：导航守卫里查 WASM SQLite 偏重，且游记不在 content 里，覆盖不到。

## 数据布局

### content/

```
content/
├─ zh/
│  ├─ friends.md
│  └─ posts/{daily,fiddling,notes,projects}/*.md
├─ en/
└─ ja/
```

迁移用 `git mv`，保留文件历史。

```ts
// content.config.ts
const makeCollection = (locale: string) => defineCollection({
  type: 'page',
  source: { include: `${locale}/**`, prefix: '' },
  schema: articleSchema,
})

export const collections = {
  content_zh: makeCollection('zh'),
  content_en: makeCollection('en'),
  content_ja: makeCollection('ja'),
}
```

`defineSitemapSchema` 当前挂在单个 collection 上，需扩展到三个。

### 分类改为语言无关 id

44 个文件的 frontmatter 由 `categories: [日常]` 改为 `categories: [daily]`。

```ts
// blog.config.ts
categories: {
  fiddling: { icon: 'tabler:tool',     color: '#33aaff' },
  projects: { icon: 'tabler:code',     color: '#7777ff' },
  notes:    { icon: 'tabler:notebook', color: '#33bbaa' },
  daily:    { icon: 'tabler:leaf',     color: '#ff7777' },
},
defaultCategory: 'notes',
```

`getCategoryIcon`、`getCategoryColor` 与 `useCategory` 的去重逻辑按 id 工作，无需修改；只有展示处套一层 `t()`。`Filter.vue` 中硬编码的「全部分类」进词条表。

### 游记

游记正文是散文（关西篇约 75 条可翻译字符串，韩国篇约 128 条），按语言分目录，与文章同构：

```
app/travels/{zh,en,ja}/{kansai-202504,korea-202510}.yaml
```

`app/travels/index.ts` 现在要求手工 `import` 并登记每篇，`nuxt.config.ts` 另行读取文件文本推导预渲染路由与草稿状态，同一份事实维护在两处。三种语言会把这份手工负担变成三倍。改用 `import.meta.glob` 自动发现，登记与草稿判定统一收敛到清单模块。

## i18n 清单模块

新增 `modules/i18n-manifest/`，沿用 `modules/anti-mirror/` 的模式。构建期执行：

1. 扫描 `content/{zh,en,ja}/**/*.md`，按与运行时一致的规则推导路由路径（剥语言段 → 剥 `/posts` 前缀，或使用 `permalink`）。
2. 扫描 `app/travels/{zh,en,ja}/*.yaml`，推导 `/travels/<slug>`，读取顶层 `draft: true` 排除草稿。
3. 经虚拟模块 `#build/i18n-manifest` 把映射编译进 bundle。44 篇 × 3 加游记，原始体积约 3–5 KB，gzip 后约 1 KB，无运行时请求。
4. 向 nitro 提供预渲染路由表，替换 `nuxt.config.ts` 中现有的游记路由推导逻辑。

```ts
// #build/i18n-manifest，key 为不带语言前缀的路径
export const manifest: Record<string, Locale[]> = {
  '/daily/anti-chronic-gastritis': ['zh', 'en'],
  '/travels/kansai-202504':        ['zh', 'ja'],
}
```

清单中查不到的路径按「所有语言都有」处理。`/archive`、`/friends`、`/media` 这类应用页面由 i18n 为每个语言生成，只有走 catch-all 的内容页需要查表。

四个消费方：导航中间件、语言切换器的灰显状态、hreflang 的 alternate 列表、预渲染路由生成。

## 路由与语言决策

### 路由策略

```ts
i18n: {
  locales: [
    { code: 'zh', language: 'zh-CN', name: '中' },
    { code: 'en', language: 'en-US', name: 'En' },
    { code: 'ja', language: 'ja-JP', name: 'あ' },
  ],
  strategy: 'prefix_except_default',
  defaultLocale: 'zh',
  detectBrowserLanguage: false,
  lazy: true,
  langDir: 'locales/',
}
```

`detectBrowserLanguage` 必须关闭。它只在入口判断一次且不认识清单，与本设计的规则竞争，同时启用会导致双重跳转。

偏好存储用 `useCookie('blog_locale')`。在 `prefix_except_default` 下「设置语言」等同于「导航」，因此 cookie 是纯粹的偏好存储，与 i18n 的路由职责不重叠。

### 决策函数

纯函数 `decideLocale(path)`：

```ts
const preferred = cookie.value ?? detectFromNavigator()  // 无 cookie 才看浏览器
if (!preferred) return
if (!cookie.value) cookie.value = preferred              // 固化，只写这一次
if (preferred === currentLocale(path)) return
const available = manifest[stripLocale(path)]
if (available && !available.includes(preferred)) return  // 缺译文，停在当前页
return navigateTo(localePath(stripLocale(path), preferred))
```

缺译文时停在当前页，语言与内容保持一致（界面也维持当前语言）。cookie 已固化，读者继续浏览到下一个有该语言版本的页面时会自动进入偏好语言。

### 执行时机

单一入口 `app/middleware/01.locale-preference.global.ts`，以 `import.meta.client` 守卫。首屏与后续导航共用同一份逻辑。

`01.` 前缀是因为 Nuxt 按文件名字母序执行全局中间件，需确保排在 `@nuxtjs/i18n` 注入的中间件之后。

客户端守卫使该中间件不参与服务端与预渲染输出，服务端与首次水合渲染同一份 HTML，此路径不产生 hydration mismatch。重定向切换的是路由而非当前路由的渲染结果，新路由整页重渲。代价是首屏会有一次错误语言的绘制。

### 手输不存在的语言版本

`/en/daily/foo` 而 en 版不存在时，catch-all 查 `content_en` 得到 null，抛 `createError({ statusCode: 404 })`。

## 界面文案

```
i18n/locales/{zh,en,ja}.ts
```

中文是唯一真源，另外两种从它取类型：

```ts
// zh.ts —— 不写 as const，值推断为 string
const zh = {
  nav:  { archive: '归档', friends: '友链' },
  post: { words: '{n} 字', readingTime: '阅读约 {n} 分钟' },
}
export default zh
export type MessageSchema = typeof zh
```

```ts
// ja.ts
import type { MessageSchema } from './zh'
const ja: MessageSchema = { /* ... */ }  // 漏一条、多一条、层级不对均编译报错
export default ja
```

再补 `i18n.d.ts` 增广 `DefineLocaleMessage`，使模板中 `$t('nav.archiv')` 这类拼写错误在调用处报错。

两层合起来：第一层保证没有漏翻的词条，第二层保证没有写错的 key。等价于 Hugo 的 `--printI18nWarnings`，但提前到编译期。

`lazy: true` 使中文读者不下载 en／ja 的词条包。

约 314 行文案分布在 97 个文件中。Nuxt 生态没有 Docusaurus `write-translations` 的等价工具，需手工抽取，按组件目录分批进行，每批抽完立即补齐三语（可先放占位），由类型层保证漏抽编译不过。

`app.config.ts` 中 `stats.wordCount: '约7万'` 一类硬编码中文同样进词条表。

## 语言切换器

新增 `app/components/blog/LangToggle.vue`，插入 `BlogSidebar.vue` 的 `.sidebar-footer`，位于 `<BlogThemeToggle />` 之前。

三个按钮遍历 i18n 配置里的 `locales`，标签取各项的 `name`（`中`／`En`／`あ`）。这些标签不进词条表——它们是各语言自称，在任何语言环境下都是这个形态。

active 态由当前路由的语言决定。该值服务端与客户端一致，因此不需要 `ThemeToggle.vue` 那个 `mounted` 守卫。ThemeToggle 需要守卫是因为偏好存在 localStorage、服务端不可知；语言在 URL 里。

当前页没有某语言版本时（查清单），该按钮 `disabled` 并灰显，`v-tip` 提示该页暂无对应语言版本（提示文案本身需翻译）。点击可用按钮时写 cookie，再 `navigateTo(switchLocalePath(code))`。

`あ` 单独挂 `:lang(ja)`，使其落到日文字体，否则会渲染成中文字形。

样式需与 ThemeToggle 完全一致（两个胶囊上下相邻）。把胶囊样式抽成 `app/assets/css/_mixin.scss` 中的 mixin，加入 `vite.css.preprocessorOptions.scss.additionalData` 一并注入，两个组件各自 `@include`。共用样式而不共用逻辑。

不复用 `ZRadioGroup`：那是通栏方块样式，与胶囊外观不同。

## 周边适配

### routeRules 与预渲染

`nuxt.config.ts` 中所有按路径写死的规则在加前缀后只覆盖中文：

| 现有规则 | 缺失覆盖 |
|---|---|
| `'/media': { ssr: false }` | `/en/media`、`/ja/media` 会走 SSR，破坏该页依赖 `ssr:false` 的首帧 query 读取 |
| `'/memos/**': { isr: 600 }` | 两个前缀版本退化为普通预渲染 |
| `/atom.xml`、`/subscriptions.opml` 的 Content-Type header | 同上 |
| `nitro.prerender.routes` 中显式登记的 `/media` | ja／en 版不会生成 |

routeRules 改为从一张基准表按 locales 程序化展开，新增语言时自动跟上。预渲染路由表由清单模块统一产出。

### 字体

JP 字体按 locale 条件注入 head。站点按语言分别预渲染，因此只有 ja 页面的 head 中出现 Noto Sans／Serif JP 的 link，中英文读者不承担该流量。

`font.scss` 增加 `:lang(ja)` 分支覆盖 `--font-basic` 与 `--font-serif`。

已知缺口：`--font-creative` 是抖音美好体（`DOUYINSANSBOLD-GB`），GB 字库无假名覆盖，日语页面用到该字体处需配 JP 兜底。

### 订阅源

`/atom.xml`（中）、`/en/atom.xml`、`/ja/atom.xml` 三份，各查各的 collection，各自设置 `language` 字段。抽取共用 builder，三个薄路由。head 中的 `rel="alternate"` 指向当前语言那份。

`blog.config.ts` 的 `myFeed`（用于 OPML 与友链页）继续指向中文那份。

### hreflang 与 sitemap

@nuxtjs/i18n 会为所有配置的 locale 自动发 hreflang，但它不知道哪些页面真有译文，会为不存在的页面发出 alternate。关闭其自动 SEO head，改由清单驱动，只列真实存在的语言，`x-default` 指向中文。

### 搜索与日期

- `Search.vue:10` 的 `Intl.Segmenter(appConfig.language)` 改为当前 locale；`queryCollectionSearchSections` 的 collection 名跟随切换。搜索只搜当前语言。
- `Date.vue:58`、`FeedCard.vue:79`、`memos/[id].vue` 中的 locale 参数改为当前 locale。
- `blogConfig.timeZone: 'Asia/Shanghai'` 保持不变，它描述作者发文时区，与读者语言无关。

### 评论

无改动。`Comment.vue` 已使用路由路径作为 page key，`/daily/foo` 与 `/ja/daily/foo` 自然分为两条线程。中文侧的 key 与当前完全一致，历史线程不受影响。

## 待验证前提

`source: { include: 'zh/**', prefix: '' }` 剥掉语言段后，`nuxt.config.ts:293` 的 `content:file:afterParse` hook 看到的 `path` 是否仍为 `/posts/...`。本设计假定是，因而该 hook 无需改动。此假定无法靠读代码确认，需在实施第一步跑一次构建打印 `ctx.content.path` 的实际值。若结论相反，该 hook 需改为先剥语言段，不影响整体架构。

**实测结论（2026-09-09）**：情况 A 成立。将 `content/posts`、`content/friends.md` 临时迁入 `content/zh/`，`content.config.ts` 改为单一 collection `source: { include: 'zh/**', prefix: '' }` 后，在 `content:file:afterParse` 里打印 `ctx.content.path`，构建输出为 `/posts/daily/anti-chronic-gastritis`、`/friends` 等——语言段已被 `prefix: ''` 剥净，`path` 不含 `/zh` 前缀。`hidePostPrefix` 剥离 `/posts` 前缀后得到的最终路径与改动前逐字节一致（`.output/public/daily/anti-chronic-gastritis/index.html` 存在）。因此 `content:file:afterParse` hook **无需改动**，可按原假定推进后续任务。

## 验收与验证

### 行为

- 中文 URL 与改动前逐字节一致，`/daily/anti-chronic-gastritis` 等路径不变。
- 浏览器语言为日语且无 cookie 时，进入任意无前缀路径会跳到对应的 `/ja/` 路径，并写入 cookie；再次访问不再触发检测。
- 目标语言在当前页无译文时不跳转，页面停在当前语言，cookie 仍被写入；导航到有译文的页面时自动进入偏好语言。
- 手动点击切换器会覆盖 cookie。
- 手输 `/en/<无译文路径>` 返回 404。
- 中英日三种语言的评论各自成线程，中文线程沿用现有 key。

### 工程

- `decideLocale` 的单元测试覆盖 cookie 有无 × 浏览器语言 × 清单命中／未命中的排列，使用 `node:test` 与 `node:assert/strict`，与仓库现有测试约定一致。
- 清单模块的单元测试：喂入 fixture 目录树，断言产出的映射与预渲染路由表。
- `nuxt typecheck` 通过即证明三语词条完整且无错误 key。
- 构建产物中不存在未翻译文章的 `/en/` 或 `/ja/` 页面。
- `/en/media` 与 `/ja/media` 的 routeRules 与 `/media` 一致。

### 视觉

- 语言切换器位于深色模式切换正上方，两者外观一致。
- `あ` 使用日文字形。
- 日语页面的正文汉字使用 JP 字形。
- 当前页不可用的语言按钮呈灰显且不可点击。
- 验证方式：生产构建 + puppeteer-core 驱动系统 Chrome。dev 下 headless 会卡在 Vite HMR。
